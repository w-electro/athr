# العرض التقديمي — كيف يُبنى

ملفّ `athr-pitch-ar.pptx` في جذر المستودع مولَّد، لا مكتوبٌ بيد. وهذا
المجلّد هو مصدره.

```bash
node tools/deck/build.cjs          # يكتب athr-pitch-ar.pptx
python tools/deck/morph.py         # يضيف انتقال Morph إلى الملفّ نفسه
```

الترتيب مقصود: `morph.py` يعدّل XML الشرائح بعد توليدها، فتشغيله قبل
البناء لا معنى له، وتشغيله مرّتين يسقط عند تأكيدٍ داخله.

## لماذا خطوتان

pptxgenjs لا يكتب انتقال Morph — وهو الانتقال الذي يجعل العنوان ينساب
بين شريحةٍ وأخرى بدل أن يُقطع. فيُضاف بعد التوليد وسمًا في `<p:sld>`،
ومعه اسمٌ يبدأ بعلامتَي تعجّب (`!!title`) على عنوان كلّ شريحة: بهذا
يزاوج PowerPoint العنوانَين يقينًا لا تخمينًا.

## الرسوم

```bash
python tools/deck/art/glyphs.py    # رموز النقش الصخري  -> assets/ic-*.png
python tools/deck/art/cover.py     # غلاف الشريحة الأولى -> assets/cover.jpg
python tools/deck/art/thumbs.py    # مصغّرا المخطّط       -> assets/thumb-*.jpg
```

الثلاثة تقرأ من `public/photos/` وتكتب في `assets/`، فتشغيلها يعيد
إنتاج ما هو موجود بالضبط. ولا مكتبة SVG هنا: `cairosvg` يحتاج
`libcairo` وهي غائبة عن ويندوز، فالرسم بـPIL مباشرةً.

## ملفّات لا يعيدها سكربت

هذه في `assets/` ولا مولّد لها، فلا تحذفها:

| الملفّ | من أين |
|---|---|
| `glyph-ibex.png` | وعل `Petroglyph.jsx` مُلتقطًا من المتصفّح |
| `app-welcome.png` · `app-site.png` | لقطتان من التطبيق بعرض 412 بكسل |
| `qr.png` | رمز الاستجابة لعنوان النشر |

## الخطوط

الشرائح تستعمل خطَّي الموقع: **Reem Kufi** للشعار و**Tajawal** للنصّ
(كلاهما SIL OFL). فإن لم يكونا مثبَّتين على الجهاز الذي يعرض، استبدل
PowerPoint بهما غيرَهما وتغيّر المقاس. ولهذا يُشحن `athr-pitch-ar.pdf`
إلى جانب العرض: يحمل الخطوط في جوفه، وإن فقَد انتقال Morph.
