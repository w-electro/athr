# أثر · دليل حائل التراثي الذكي

تطبيق ويب يحوّل الهاتف إلى مرشد سياحي ذكي في منطقة حائل. يوجّه الزائر كاميرته
نحو نقش صخري أو مبنى تاريخي، فيتعرّف "أثر" على الموقع ويروي قصته — نصًا وصوتًا —
ثم يبني له مسار رحلة مرتّبًا حسب اهتماماته والطقس. **بـ29 لغة**، تُختار تلقائيًا
حسب لغة جهاز الزائر.

بُني لهاكاثون **AJA AI** — مسار السياحة.

**الموقع الحيّ:** https://w-electro.github.io/athr/

---

## اللغات

يفتح التطبيق على شاشة اختيار لغة، وقد اختار سلفًا لغة جهاز الزائر
(`navigator.languages`)، فيكفيه الضغط على "ابدأ".

**29 لغة، كلها مترجمة فعليًا** — لا قائمة طويلة نصفها لا يعمل. تغطي هذه اللغات
اللغات الأم لأغلب السياح الوافدين إلى السعودية:

> العربية · English · Français · Español · Deutsch · Italiano · Português ·
> Nederlands · Polski · Русский · Українська · Ελληνικά · Türkçe · فارسی ·
> اردو · עברית · हिन्दी · বাংলা · தமிழ் · 简体中文 · 繁體中文 · 日本語 ·
> 한국어 · Bahasa Indonesia · Bahasa Melayu · ไทย · Tiếng Việt · Filipino ·
> Kiswahili

أربع منها تُكتب من اليمين لليسار، والتخطيط ينقلب لها بالكامل تلقائيًا.

### لماذا 29 وليس "كل اللغات"؟

في العالم نحو 7000 لغة حية. لا توجد وسيلة — مجانية أو مدفوعة — لترجمة محتوى
تراثي مفصّل إليها كلها بجودة تحترم القارئ. قائمة فيها 200 لغة نصفها فارغ تنهار
أمام أول محكّم يجرّب لغته. فاخترنا التغطية الحقيقية على العدد المعلن.

### الترجمة كاملة، لا الواجهة فقط

كل لغة من الـ29 تشمل **الواجهة والمحتوى التراثي معًا**: قصص المواقع الأربعة
بفصولها الأربعة، والسرد الصوتي بمقاطعه، والحقائق، ونصائح الزيارة، وأدلّة
المسح. لا لغة تتراجع إلى لغة أخرى.

| الطبقة | أين | ما فيها |
|---|---|---|
| البنية | `src/data/sites.js` | الإحداثيات، المدد، التصنيفات، الصور، توقيتات مقاطع السرد — لا تُترجم أبدًا |
| النص العربي | `src/data/sites.js` | لغة الأساس |
| النص المترجم | `src/data/content/<code>.js` | 28 ملفًا، ملف لكل لغة |

فصل البنية عن النص مقصود: لا يمكن أن تختلف مدة زيارة أو توقيت مقطع صوتي بين
لغة وأخرى مهما تُرجم النص. اختبار `content.test.js` يتحقق من ذلك في الـ28 ملفًا.

### تحميل كسول لكل لغة

قصص المواقع بـ28 لغة تزن نحو 700 كيلوبايت. لو حُمّلت دفعةً واحدة لأنزل كلُّ
زائر محتوى 27 لغة لن يقرأها — وهذا تحديدًا ما لا يُحتمل في الموقع الذي بُني
له التطبيق.

لذلك يقسّم `src/data/content/index.js` كل لغة إلى حزمة مستقلة عبر
`import.meta.glob` الكسول، ويحمّل `main.jsx` لغة المستخدم وحدها قبل أول عرض:

| | قبل التقسيم | بعده |
|---|---|---|
| الحزمة الأولى | 311 ك.ب مضغوطة | 137 ك.ب |
| محتوى اللغة | مضمّن | ~7 ك.ب لحزمة واحدة |

في الاختبارات تُملأ الذاكرة مسبقًا (`primeContentCache` في `src/test/setup.js`)
لتبقى فحوص الشاشات متزامنة.

### إضافة لغة واجهة جديدة

1. أضف مدخلًا في `src/i18n/languages.js`
2. انسخ `src/i18n/locales/en.js` إلى `<code>.js` وترجم القيم
3. سجّله في `src/i18n/locales/index.js`

اختبار `i18n.test.js` يتحقق تلقائيًا من اكتمال المفاتيح وسلامة المتغيّرات
(`{count}`, `{temp}` …) ويسقط عند أي نقص.

### إضافة لغة بمحتوى تراثي كامل

انسخ `src/data/content/en.js` إلى `<code>.js` وترجمه. لا حاجة لتسجيله في أي
مكان: `import.meta.glob` يلتقطه تلقائيًا.

**تنبيه:** لا تغيّر قيم `at` في مقاطع السرد. هي توقيتات بنيوية تُبقي النص
متزامنًا مع شريط التشغيل، واختبار `content.test.js` يرفض أي انحراف عنها.

## التشغيل محليًا

المتطلّب الوحيد: **Node.js 18 أو أحدث**.

```bash
npm install      # مرة واحدة
npm run dev      # يفتح http://localhost:5173
```

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | خادم التطوير مع التحديث الفوري |
| `npm test` | تشغيل الاختبارات مرة واحدة (49 اختبارًا) |
| `npm run test:watch` | الاختبارات في وضع المراقبة أثناء التطوير |
| `npm run build` | حزمة الإنتاج في `dist/` |
| `npm run preview` | معاينة حزمة الإنتاج محليًا |

> **مهم قبل العرض:** الكاميرا لا تعمل إلا على `localhost` أو عبر **HTTPS**.
> فتح التطبيق من جوالك عبر `http://192.168.x.x:5173` **سيفشل** في فتح الكاميرا.
> الحل: انشره على Vercel أو Netlify (مجاني، وHTTPS تلقائي) واعرض من الرابط.

### المبدأ المعماري

الشاشات لا تحتوي منطقًا. كل قرار (أي موقع في الصورة؟ ما ترتيب المسار؟)
يعيش في `src/lib/` كدوال خالصة قابلة للاختبار والاستبدال. هذا ما يجعل الانتقال
من المحاكاة إلى الذكاء الحقيقي تغييرًا في ملف واحد لا إعادة كتابة.

**ولا تُنتج ملفات المنطق نصًا بشريًا إطلاقًا.** `itinerary.js` و`weather.js`
تُرجعان مفاتيح ترجمة ومتغيّرات، والواجهة تترجم. لولا ذلك لاحتجنا نسخة من محرّك
التخطيط لكل لغة من الـ29.

## الدليل الصوتي — نطق حقيقي، مجاني

السرد يُنطق فعلًا عبر **Web Speech API** المدمجة في المتصفح:

- **مجانية بلا حدود** — لا مفاتيح ولا حساب ولا محاسبة بالحرف
- **تعمل بلا إنترنت** على أغلب الأجهزة (الأصوات مثبّتة في نظام التشغيل)
- النص لا يغادر الجهاز

النطق يجري **مقطعًا مقطعًا** لا جملةً واحدة طويلة، لثلاثة أسباب: التزامن
مع النص يصير مضمونًا لا تخمينًا زمنيًا، وبعض المتصفحات تقطع النطق الطويل
بعد ~15 ثانية، ويستطيع الزائر القفز إلى أي جملة.

**وإن لم يملك الجهاز صوتًا لتلك اللغة** يتراجع المشغّل تلقائيًا إلى العرض
النصّي المتزامن. لا رسالة خطأ — دليل يعمل. الأصوات المتاحة تخصّ جهاز
الزائر لا التطبيق، فهاتف قد يملك صوتًا عربيًا ممتازًا وآخر لا يملك أي صوت
تاميلي.

## التصميم

**الليل هو الأرضية، والتراكوتا هو الضوء.** ألوان العميل الثلاثة كما هي، لكن
بأوزان مقلوبة — والسبب من الموضوع نفسه: نقوش جبة لا تُقرأ إلا في الضوء المائل
عند الفجر والغروب، والتطبيق يُستخدم في العراء تحت وهج الشمس حيث تريح الواجهة
الداكنة العين، وسماء النفود ليلًا هي الصورة الذهنية للمنطقة.

**التوقيع البصري:** لا دائرة تحميل في التطبيق كله. مكانها نقش من جبة يُرسم
أمامك خطًّا خطًّا — بالطريقة التي نُقر بها الأصل على الصخر. الكود في
`src/components/Petroglyph.jsx`، وهو SVG خالص ببضع مئات من البايتات.

**الخطوط بأدوار محددة:**

| الخط | الدور | السبب |
|---|---|---|
| Reem Kufi | العناوين | كوفي زاويّ محفور — صدى مباشر لنقوش الصخر |
| Tajawal | نص المحتوى العربي | طلب العميل، وأوضح خط عربي للقراءة الطويلة |
| Noto Sans | واجهة الـ29 لغة | اسمها من "no more tofu" — العائلة الوحيدة التي تغطي كل هذه الكتابات بلا مربعات فارغة |
| IBM Plex Mono | الأرقام والبيانات | مسافات وأوقات ونسب ثقة تُقرأ كقراءة جهاز ميداني |

**الكتابات العربية الثلاث لا تتشارك خطًّا واحدًا:**

| اللغة | الخط | لماذا |
|---|---|---|
| العربية | Tajawal | خط العميل، وأوضح للقراءة الطويلة |
| الفارسية | Vazirmatn | تحتاج گ چ پ ژ وياءً فارسية (ی) وكافًا فارسية (ک) لا يحملها Tajawal |
| الأردية | Noto Nastaliq Urdu | تُكتب تقليديًا بالنستعليق المائل لا بالنسخ، ولها ٹ ڈ ڑ ں ھ ے |

يُحمَّل خطّ الفارسية أو الأردية عند اختيار اللغة فقط (`ensureScriptFont` في
`src/i18n/index.jsx`)، لأن هذه الخطوط تغطّي النطاق اليونيكودي نفسه فلو حُمّلت
كلّها لأخذ كلُّ قارئٍ عربيّ أربعة خطوط لا يحتاج منها إلا واحدًا.

> **ثلاثة تنبيهات لمن يعدّل التصميم أو الترجمة:**
>
> 1. لا تطبّق `letter-spacing` على العربية أو الفارسية أو الأردية. هذه كتابات
>    متّصلة، والتباعد يفكّ التحام الحروف فتصير الكلمة غير مقروءة — وهو خطأ
>    إملائيّ لا خيار جماليّ. القاعدة مضبوطة في `src/index.css` حسب `lang`.
> 2. رتّب قوائم الخطوط بحيث يأتي `Noto Sans` أوّلًا في الفارسية والأردية.
>    المتصفح يختار الخط لكل حرفٍ على حدة، وخطوط النستعليق تحمل حروفًا لاتينية
>    أيضًا، فلو تقدّمت لعُرض النصّ الإنجليزيّ بخطٍّ غريب.
> 3. لا تكتب أرقامًا هندية شرقية (۱۲۳) في ملفات الترجمة. بقيّة التطبيق يعرض
>    الأرقام لاتينيةً بخط IBM Plex Mono، والخلط يُظهر نظامَي ترقيم في شاشة
>    واحدة. اختبار `i18n.test.js` يمنع ذلك.
> 4. قاعدة `.eyebrow` تضيف التباعد للكتابات اللاتينية والسيريلية واليونانية
>    فقط — بالإضافة لا بالاستثناء. الكورية واليابانية والصينية والتايلندية
>    والهندية تتبعثر بالتباعد كما تتبعثر العربية.

## الصور

صور حقيقية للمواقع من ويكيميديا كومنز برخص حرة (أغلبها من هيئة التراث
السعودية)، مصغَّرة ومضغوطة — المجموع نحو 1 ميغابايت لثماني صور.

النسب والرخص في [`CREDITS.md`](CREDITS.md)، ويعرضها التطبيق أسفل شاشة تفاصيل
كل موقع. **رخصة CC BY-SA تُلزم بذلك — لا تحذف النسب.**

**لإضافة صورك بعد الزيارة الميدانية:** ضع الملف في `public/photos/` وأضف مساره
إلى حقل `photos` للموقع في `src/data/sites.js`. الأولى في المصفوفة تصبح الغلاف
تلقائيًا، بلا تعديل أي كومبوننت.

## التعرّف على الصور: ثلاثة مسارات

الشاشة تنادي `recognizeSite()` فقط. المزوّد يُختار من `.env` بلا أي تعديل كود.

### 1. `mock` — الافتراضي (مجاني)

محاكاة محلية بلا إنترنت ولا مفاتيح. مناسبة للعرض والتطوير.
في شاشة المسح، زر ⚙︎ يفتح لوحة تتيح **تثبيت النتيجة على موقع محدد** —
استخدمها أثناء العرض حين توجّه الكاميرا نحو صورة مطبوعة.

### 2. `local` — تعرّف حقيقي، مجاني تمامًا ✅ الموصى به

نموذج **DINOv3** من Meta يعمل **داخل متصفح الزائر** عبر
[transformers.js](https://github.com/huggingface/transformers.js).

**لماذا هو الخيار الأقوى هنا:**
- صفر تكلفة وصفر خوادم — لا فواتير استهلاك إطلاقًا.
- **يعمل بلا إنترنت** بعد التحميل الأول. جبة تبعد 95 كم عن حائل وتغطيتها ضعيفة،
  فهذه ليست ميزة تقنية بل شرط عملي لنجاح الفكرة على أرض الواقع.
- الصورة لا تغادر جهاز المستخدم — خصوصية كاملة.

**ولا يحتاج تدريبًا.** النموذج يحوّل الصورة إلى 384 رقمًا تصف شكلها، فيصير
سؤال «ما هذا الموقع؟» مقارنةً حسابية مع صورك المرجعية. وإضافة موقع خامس =
إضافة صوره فقط، بلا إعادة تدريب — وهو ما لا يوفّره أي مصنِّف مدرَّب.

**التفعيل بعد رحلتك الميدانية:**

```bash
npm install @huggingface/transformers
```

1. صوّر ١٥–٣٠ صورة لكل موقع من زوايا وإضاءات مختلفة، و٥٠ صورة «سلبية»
   لا تخصّ أي موقع (رمل، سماء، صخر عادي).
2. شغّل [`notebooks/build-reference-index.ipynb`](notebooks/) على Kaggle
   مجانًا وبلا GPU. يبني `reference-index.json`، **ويقيس دقّة النظام**
   ويقترح عتبة «لا أعرف».
3. ضع الملف في `public/`، واضبط `SIMILARITY_THRESHOLD` بالرقم المقترح.
4. في `.env`: `VITE_RECOGNITION_PROVIDER=local`

**لماذا فهرس جاهز بدل الحساب في المتصفح؟** لأن المتصفح عندئذٍ لا يُنزّل صور
المرجع إطلاقًا، بل ملف أرقام صغير. وإن غاب الفهرس يتراجع التطبيق تلقائيًا
إلى حساب المتجهات من `site.photos` وقت التشغيل.

> ⚠️ `MODEL_ID` و`MODEL_DTYPE` في `recognition.local.js` يجب أن يطابقا ما في
> الدفتر. النموذجان المختلفان يُنتجان أرقامًا لا تعني الشيء نفسه، فتصبح
> النتائج عشوائية. التطبيق يتحقّق من البصمة ويرفض الفهرس غير المطابق.

### إضافة مزوّد خارجي لاحقًا

سجلّ المزوّدين في `recognition.js` يقبل أي دالة تُرجع الشكل الموحّد. إن
توفّر لك يومًا رصيد خدمة رؤية خارجية، أضف دالة واحدة هناك — ولا يتغيّر شيء
في بقية التطبيق.

> **قاعدة أمان إن فعلت:** لا تضع مفتاح API في `.env` مسبوقًا بـ `VITE_`.
> أي متغيّر كذلك يُحقن في حزمة المتصفح ويستطيع أي زائر قراءته. المفاتيح
> تعيش في بيئة الخادم وحدها.

## يعمل بلا إنترنت — فعلًا

التطبيق **تطبيق ويب تقدّمي (PWA)** بعامل خدمة يخزّن قالبه وصوره مسبقًا.

هذا ليس تحسينًا تجميليًا هنا: جبة تبعد 95 كم عن حائل وتغطيتها ضعيفة.
بدون عامل الخدمة كان فتح التطبيق هناك بلا إشارة يعطي **صفحة بيضاء** مهما
كانت بقية الشيفرة سليمة.

| الطبقة | كيف تُخزَّن |
|---|---|
| قالب التطبيق والصور (~2 م.ب) | تخزين مسبق عند أول زيارة |
| الخطوط من Google Fonts | تخزين عند أول استخدام |

## النشر

**الموقع الحيّ:** https://w-electro.github.io/athr/

### تحديث الموقع بعد أي تعديل

```bash
npm run deploy
```

### النشر على مضيف آخر

مسار النشر مضبوط على `/athr/` لأن GitHub Pages يقدّم المشروع من مسار فرعي،
وعامل الخدمة يحتاج مسارًا مطلقًا ليعرف نطاقه. إن نشرت على جذر نطاق
(Netlify أو Vercel):

```bash
ATHR_BASE=/ npm run build
```

أمر واحد: يبني المشروع ويدفع مجلد `dist` إلى فرع `gh-pages`، وGitHub Pages
يقدّمه مباشرة. التحديث يظهر خلال دقيقة تقريبًا.

### لماذا النشر يدوي لا تلقائي؟

ملف `.github/workflows/deploy.yml` جاهز للنشر التلقائي عند كل دفعة، لكنه
معطّل حاليًا لأن حساب GitHub مقفل بسبب مشكلة فوترة فلا تعمل الـ Actions.
بعد حلها (وهي مجانية بلا حدود للمستودعات العامة): أعِد تفعيل محفّز `push`
في الملف، وغيّر مصدر Pages إلى GitHub Actions من `Settings → Pages`.

### ملاحظة على التوجيه

على GitHub Pages نستخدم `HashRouter` (روابط مثل `#/scan`) لأن الاستضافة
الساكنة بلا إعادة توجيه من الخادم، فتحديث الصفحة على مسار عادي يعطي 404.

إن انتقلت لاحقًا إلى Vercel أو Netlify — و`vercel.json` و`public/_redirects`
جاهزان لهما — يمكنك العودة إلى `BrowserRouter` في `src/main.jsx` لروابط أنظف:

```bash
npm i -g vercel && vercel --prod
```
